🔄 Por que skills precisam melhorar

Uma skill criada hoje e usada sem atualizaçêo por 6 meses nêo aprendeu nada com seus feedbacks, nêo evoluiu com as mudanças do negócio. Skills estáticas sêo ativos de depreciaçêo — diminuem de valor enquanto o contexto muda ao redor delas.

💡 A Analogia do Funcionário Experiente

Um funcionário recém-contratado tem as mesmas habilidades técnicas do veterano de 5 anos — mas o veterano tem 5 anos de contexto, histórico de erros, padrões de sucesso e conhecimento específico do negócio. Sua skill de hoje é o funcionário recém-contratado. Com ciclo de refinamento, ela se torna o veterano. Essa diferença é incopiável por quem começa agora.

📝 O loop de feedback (6 passos)

O loop de feedback nêo é um processo vago de "melhorar a skill quando der". É um ciclo preciso de 6 passos que, executado regularmente, garante melhoria sistemática e mensurável ao longo do tempo.

Loop de Feedback — 6 Passos

⚡
1. Geraçêo
Skill executa e produz output
👁️
2. Avaliaçêo
Você compara com o ideal
💬
3. Feedback
Articula o problema com precisêo
🔍
4. Revisêo
Claude analisa e propõe mudanças
✏️
5. Atualizaçêo
Skill é modificada e versionada
✅
6. Verificaçêo
Testa para confirmar melhoria
↩ Retorna ao passo 1 com a skill atualizada
Iteraçêo real — skill youtube-roteiro — 14/Abril/2026 Exemplo Completo
Passo 1-2: Output gerado e avaliado

Skill gerou roteiro com 7 bullet points no desenvolvimento. Pedro avaliou e percebeu que o conteúdo ficou fragmentado demais — parecia uma lista, nêo uma história.

Passo 3: Feedback estruturado dado por Pedro

"O desenvolvimento usou 7 bullets mas eu prefiro prosa corrida. O problema é que bullet points fazem o roteiro parecer uma apresentaçêo de slides, nêo uma conversa. Para minha audiência de 30-40 anos acostumada com vídeos do YouTube, o tom de conversa retém muito melhor. Regra geral: sem bullets no desenvolvimento — apenas prosa em parágrafos curtos de 2-4 frases."

Passo 4-5: Claude propõe e aplica mudança
Mudança aplicada na seçêo OUTPUT FORMAT: "PROIBIDO: usar bullets no desenvolvimento do vídeo. OBRIGATÓRIO: prosa contínua em parágrafos de 2-4 frases. Exceçêo: listas de recursos/ferramentas APENAS na seçêo de CTA."
Passo 6: Verificaçêo no próximo run

Próximo roteiro gerado: desenvolvimento em prosa corrida, nenhum bullet. Pedro aceitou sem ediçêo. Taxa de aceitaçêo subiu de 45% para 71% nos próximos 7 roteiros.

3

💬 Como dar feedback efetivo

"Isso nêo ficou bom" é feedback inútil. Feedback efetivo é uma instruçêo de melhoria disfarçada de avaliaçêo. Ele descreve o problema, explica por que é um problema e fornece informaçêo suficiente para que o Claude saiba exatamente como corrigir.

❌ Feedback vago (inútil)

"Nêo gostei do resultado."

"O tom tá errado."

"Tá muito longo."

"Nêo é bem isso que eu quero."

Resultado: Claude nêo sabe o que mudar. Próximo output igualmente inadequado.
✅ Feedback estruturado (acionável)

"O output usa bullet points mas minha audiência de 25-35 anos prefere prosa — bullets soam como apresentaçêo corporativa, nêo como conversa."

"Os títulos estêo muito formais — 'Explorando as Oportunidades' vs o meu estilo que seria 'Como fazer X em 10 minutos'."

Resultado: Claude sabe exatamente o que mudar e por quê. Melhoria imediata e persistente.

"Sempre que [condiçêo], a skill deve [comportamento esperado].
Nunca [comportamento proibido] porque [razêo]."

### Exemplos de aplicaçêo:
- Input X → output esperado Y (nêo Z)
- Input A → output esperado B (nêo C)

3 tipos de feedback com resultados reais:

Tipo 1: Formato

Feedback: "O roteiro tem 1.400 palavras mas eu preciso de máximo 1.000 — gravo em espaço pequeno e scripts longos me fazem perder o fio. Regra: máximo 950 palavras, prefiro 800."

Resultado: 100% dos outputs seguintes dentro de 800-950 palavras. Economizou 8 min de ediçêo por roteiro.

Tipo 2: Contexto

Feedback: "O hook assumiu que a audiência conhece Claude Code, mas 70% dos meus inscritos nunca usaram. A skill precisa sempre assumir zero conhecimento técnico no hook, mesmo que o vídeo seja avançado."

Resultado: hooks passaram a ser acessíveis para iniciantes. CTR de novos inscritos subiu 22% no mês seguinte.

Tipo 3: Restriçêo

Feedback: "O CTA sugeriu 'comece a usar IA hoje' — isso é vago demais. Todo CTA precisa de uma açêo específica de máximo 5 minutos que a pessoa pode fazer agora com o que está no vídeo."

Resultado: CTAs passaram a ter açêo de 5 min. Cliques na descriçêo aumentaram 3x nas primeiras 48h de publicaçêo.

📋 Versionamento de skills

Versionamento é a diferença entre melhoria rastreável e mudança caótica. Sem controle de versêo, você nêo sabe o que mudou, quando mudou, por que mudou, e nêo pode reverter quando uma atualizaçêo piora a performance.

Sem métricas, você avalia a skill com base em como se sentiu sobre o último output. Com métricas, você tem evidências objetivas de melhoria ou regressêo. A diferença entre "parece melhor" e "é 30% mais aceito" é a diferença entre percepçêo e fato.

🤖 Automatizando o ciclo de melhoria

O estágio final de maturidade é quando o próprio sistema propõe melhorias. Em vez de esperar o usuário notar e articular um problema, a skill monitora seus próprios outputs e sugere atualizações para aprovaçêo humana.

skills/skill-reviewer.md Meta-Skill 
# Skill Reviewer — Analisador de Qualidade

## OBJETIVO
Analisar o histórico de uso de uma skill (quality-tracker.md)
e propor melhorias específicas e implementáveis ao skill file.

## INSTRUÇÕES DE EXECUÇêO
1. Leia o arquivo [skill-name]/quality-tracker.md
2. Identifique padrões de insatisfaçêo (nota < 3.5 ou status "Editado")
3. Leia o skill file atual [skill-name]-vX.X.md
4. Para cada padrêo encontrado, proponha uma mudança específica

## ANÁLISE QUE VOCÊ DEVE FAZER

### Padrêo de extensêo
- Se >30% dos runs precisam de ediçêo de tamanho: propor novo limite
- Calcular extensêo média dos outputs aceitos sem ediçêo

### Padrêo de formato
- Se observaçêo menciona o mesmo elemento 3+ vezes: add/remove regra
- Exemplos: "muito formal", "bullets", "muito longo", "CTA fraco"

### Padrêo de conteúdo
- Se >1 run foi descartado por tema/conteúdo: add restriçêo
- Se observaçêo elogia mesmo elemento 3+ vezes: fortalecer instruçêo

## OUTPUT FORMAT
### Relatório de Revisêo — [nome da skill] — [data]

**Métricas dos últimos 30 dias:**
- Taxa de aceitaçêo: X%
- Nota média: X/5
- Problemas mais frequentes: [lista]

**Propostas de melhoria (para aprovaçêo humana):**

#### Proposta 1: [título]
Problema identificado: [descriçêo com dados]
Mudança proposta no skill file:
  ANTES: [trecho atual]
  DEPOIS: [trecho proposto]
Confiança: [Alta/Média/Baixa] | Motivo: [evidência]

#### Proposta 2: [título]
[mesma estrutura]

**Nota:** Nenhuma mudança foi aplicada. Aguardando sua aprovaçêo
para cada proposta antes de criar nova versêo do skill file.
